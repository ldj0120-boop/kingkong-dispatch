# 킹콩 물류 배차·정산 (프로토타입)

쿠팡 출고요청 · 센터/본사 요청 · 고객 배송 3가지 배차를 **한 통합 대장**에 모으는 웹앱입니다.
**카톡 · 엑셀로 일하던 방식은 그대로** 두고, 그 글을 붙여넣으면 칸이 채워집니다. 저장하면 열려 있는 모든 화면이 바로 바뀝니다.

| 누가 | 주소 | 하는 일 |
| --- | --- | --- |
| 킹콩 관리자(PC) | 그대로 | 카톡 요청 글 · 쿠팡 출고요청서 표 · 카톡 '대화 내보내기' 파일 붙여넣기 → 요청 등록 + 업체 글(배차 · 취소 · 회차 · 변경) 반영, 대시보드 · 대장 · 정산 |
| 더한물류(휴대폰) | `?v=더한물류` + PIN (옛 `?v=태성로지스틱스` 링크도 더한물류로 열림) | 단톡방에 보낸 글 그대로 붙여넣기(또는 직접 입력) · 기사 취소/회차/변경 버튼 · '카톡 보내기'로 같은 양식 문구 공유 |
| 매장(휴대폰) | `?s=매장이름` + 매장 PIN | 배송요청서 항목 입력 + 영수증 사진 첨부 → 배차 · 배송일 · 기사 바로 확인. 종이 요청서 · 확인서는 매장 보관 |

### 권한 · 기록
- **금액(기본 · 추가 · 사유 · 회차금액)은 더한물류만** 입력 · 수정합니다. 관리자 화면에서는 잠겨 있고, DB도 관리자 세션의 금액 변경을 거부합니다.
- **비고 · 질문**: 통합 대장 '질문' 버튼이나 상세 화면에서 물류 담당자가 묻고, 더한물류가 휴대폰 '질문' 탭에서 답합니다. 답이 없으면 대시보드 '답변 대기 질문'에 뜹니다.
- **수정 기록**: 모든 표(배차 · 고객배송 · 질문 · 영수증 · 운임표 · 지점 · 업체 · 매장 · 정산)의 추가 · 수정 · 삭제를 칸 단위 `이전 → 이후`, 누가, 언제(초까지) DB 트리거가 자동으로 남깁니다. 관리자도 고치거나 지울 수 없습니다. '수정 기록' 탭에서 보고 CSV로 내려받습니다.

### 배차 이력(타임라인)
건마다 `요청 → 배차 → 배차 취소/회차/변경 → 재배차 → 운행 완료` 가 누가 · 언제 · 어떤 기사 · 무슨 사유로 남습니다.
카톡의 "취소입니다 재배차 하겠습니다", "상차지연으로 회차 입니다" 를 붙여넣거나 버튼으로 남기면 됩니다.
회차금액을 적으면 정산에 들어갑니다(요청이 끝내 취소돼도 회차비는 정산).

```
kk-dispatch/
├─ index.html          화면(스타일 포함)
├─ app.js              동작 전부(관리자 화면 + 업체 모바일 화면)
├─ config.js           Supabase 연결값 — 비워 두면 데모 모드 · TEST_MODE · 알림 공개키
├─ sw.js · manifest.webmanifest · icon-*.png   휴대폰 홈 화면 앱 · 알림
├─ 배차요청_양식.xlsx   엑셀로 요청할 때 쓰는 양식
├─ supabase/schema.sql DB 테이블 · 보안 · 업체용 함수 · 수정 기록 · 알림 트리거
└─ supabase/functions/notify/index.ts   알림 보내는 서버 함수(Edge Function)
```

## 0. 1단계 파일럿 (build 9)

**범위** — 쿠팡 출고(`--t1`) + 진천센터 → 매장 출고(`--t2`)만. 신선(콜드체인) 센터 · 고객 배송은 2단계(`config.js` 의 `PHASE: 2`).
범위 밖 데이터는 화면 · 알림 · 붙여넣기에서 빠지거나 '2단계(제외)'로 체크 해제된 채 나옵니다. DB에는 그대로 남습니다.
구글시트는 쿠팡 시트만 보냅니다(`시트_자동보내기.gs` 의 `PHASE = 1`). 숨긴 탭도 읽습니다.

**연습 모드** — 아무 링크 끝에 `?demo=1`(끄기 `?demo=0`). 실제 DB 대신 이 기기 전용 연습 데이터(`kk_dispatch_practice_v1`)로 동작, 화면에 주황 '연습 모드'. 교육 · 시연용.
**동기화 표시** — 모든 화면에 점: 초록 실시간 연결 · 주황 연결 중/연습 · 빨강 끊김/오프라인 + 마지막으로 받은 시각. 누르면 설명 · 연습 모드 전환.

### 카톡 붙여넣기(스마트 붙여넣기) 읽는 규칙
| 읽는 것 | 예 | 들어가는 칸 |
|---|---|---|
| 출발 · 도착 | `진천센터~이천점`, `기흥센터-인천점 3plt`, 문장형 `내일 진천에서 원주점으로 12파렛` | 상차지 · 하차지 (문장형은 노랑 · 체크 해제) |
| 수량 | `18plt` · `12파렛` · 다음 줄 `18plt 배차부탁` | PLT |
| 필요 시간 | `13시 이후` · `10시까지` · `10:30 도착` · `오전/오후/야간` | 시간 |
| 날짜 | `내일` · `모레` · `11/5` · 카톡 내보내기 날짜 줄 | 운행일 |
| 특이사항 | 지게차 · 수작업 · 도크 · 대기 · 행사 · 파손 · 연락처 등 | 메모 |
| 업체 글 | `[차주정보]` · `[차량정보]` · `그룹넘버` · 취소/회차/변경 | 맞는 요청에 연결 |

판단 색: 초록 = 지점 둘 다 아는 이름 + 수량 있음 / 노랑 = 확인 필요(모르는 이름 · 문장형 · 이미 있는 요청 · 2단계) / 빨강 = 못 읽은 줄(눌러서 요청으로 추가). 고친 지점 이름은 별칭으로 기억(관리자).

### UX 메모 — 더한물류
- PC에서 링크를 열면 **관제판**(표/칸반). 표 칸에 바로 기사 · 차량 · 운임을 쓰면 칸을 벗어날 때 자동 저장(낙관적 반영, 실패 시 되돌림).
- 체크(Shift 범위) → 운행 완료 · 같은 기사/차량 넣기 · 카톡 문구를 한 번에. 칸반에서 카드를 '운행 완료'로 끌면 완료.
- 휴대폰은 기존 화면 그대로(‘PC 관제판’ ↔ ‘휴대폰 화면’ 전환). 카톡 글은 계속 붙여넣기로.

### UX 메모 — 매장
- **빠른 요청**: 날짜(오늘/내일/모레) → 입고 시간 → PLT(−/+ · 자주 쓰는 수) → 보내기. 출발은 진천센터, 도착은 우리 매장 자동.
- **최근 요청 복사**: 지난 요청의 PLT · 시간 · 특이사항을 채워 날짜만 내일로.
- 카드의 **요청 → 배차 → 입고 완료** 점으로 진행 확인, 배차되면 기사 · 차량 · 연락처와 알림. 배차 전 자기 요청은 취소 가능.

## 0-1. 1단계 시범 그룹 · 물류비 대시보드 · 그룹 알림 (build 12)
- **1단계 그룹**: 킹콩본사(이메일 로그인) · 진천센터(링크 `?g=진천센터` + PIN) · 더한물류(`?v=` + PIN). 매장(`?s=`) · 신선센터는 2단계 — `config.js` 의 `STORES_OPEN`.
  - 진천센터 만들기(SQL): `insert into stores(name, kind, pin_hash) values ('진천센터', 'center', crypt('PIN', gen_salt('bf')));`
  - 관리자 소속: `update staff set org = '킹콩백화점' where email = '...';` (기본 킹콩본사)
- **보는 범위(그룹별 격리)**: 본사 = 전체 / 진천센터 = 진천 출발·도착·진천이 요청한 건, 금액 없음(`center_list`) / 더한물류 = 자기 배정 건(`vendor_list`) / 매장 = 자기 매장(`store_list`). 동시 접속 제한 없음.
- **알림**: 배차 요청 → 더한물류 / 차량 등록(배차·재배차) → 발주처 그룹(`orderer_targets`: 본사·백화점 = 소속 관리자 이메일 기기, 센터·매장 = 그 링크로 알림 켠 기기) / 회차·기사 취소 → 본사 + 발주처. 2단계 매장·신선센터도 같은 규칙(최초 요청 그룹에 알림).
- **My View**: 관리자 대장 '내 요청' 칩 · 발주처 필터, 진천센터 '내 요청' 탭(요청자 이름 기준).
- **물류비 탭**: 기본 + 추가(대기료 · 경유비 · 기타, 사유 글자로 분류) + 회차 합산, PLT당 물류비, 운임표 대비, 정확도(금액 미입력 · 운임표 초과/미달 · 사유 없음 · 같은 구간 단가 ±30% · 중복 의심 · 운임표 없음 · 경유비 없음 · 톤수 미기재), 구간 · 톤수 · PLT · 추가운임 종류별 표. 원천 = 앱 대장 + 구글시트(숨김 탭 포함 1시간 동기화).
- **설명서 자동 갱신**: 빌드마다 화면 캡처 → PDF 재생성(아래쪽에 build 번호 · 날짜). 앱 '설명서' 창 위에 '최근 바뀐 점', 새 빌드로 처음 열면 한 번 안내.

## 1. 지금 바로 써 보기 (데모 모드, 5분)

1. 이 폴더를 새 GitHub 저장소(예: `kingkong-dispatch`)에 올립니다. GitHub Desktop: File › Add local repository → Publish.
2. 저장소 Settings › Pages › Branch `main` / `(root)` → Save.
3. 1~2분 뒤 `https://<계정>.github.io/kingkong-dispatch/` 가 열립니다.
   - 관리자 화면: 그 주소 그대로
   - 업체 화면: `…/kingkong-dispatch/?v=더한물류` (PIN 1357)
   - 매장 화면: `…/kingkong-dispatch/?s=이천점` (PIN 1111) · `?s=시그니처인천점` (2222)
   - 데모에서도 같은 브라우저의 탭끼리는 실시간으로 맞춰집니다(업체 탭에서 저장 → 관리자 탭이 바뀜)
4. 데모 모드는 **이 브라우저에만** 저장됩니다. 다른 사람과 공유하려면 2단계로.

## 2. 실제 운영 (Supabase 연결, 30분)

1. https://supabase.com 에서 새 프로젝트(Region: Seoul). 무료 요금제로 충분합니다(500MB DB).
2. SQL Editor › New query 에 `supabase/schema.sql` 전체를 붙여넣고 **Run**.
3. 같은 SQL Editor 에서 업체 · 관리자를 등록합니다(PIN 은 업체에 따로 알려 주세요).
   ```sql
   insert into vendors(name, pin_hash, types) values ('더한물류', crypt('여기PIN', gen_salt('bf')), '{coupang,center,delivery}');
   insert into staff(email, name) values ('ldj0120@kinggo.ai', '이동주');
   insert into stores(name, pin_hash) values ('이천점', crypt('매장PIN', gen_salt('bf'))), ('시그니처인천점', crypt('매장PIN', gen_salt('bf')));
   ```
4. Authentication › URL Configuration › Site URL 에 GitHub Pages 주소를 넣습니다(로그인 메일 링크가 돌아올 곳).
5. Project Settings › API 에서 `Project URL` 과 `anon public` 키를 `config.js` 에 붙여넣고 커밋 · 푸시.
6. 관리자는 이메일을 넣으면 오는 로그인 링크로 들어가고, 업체에는 `?v=업체이름` 링크 + PIN 을 보냅니다.

`type` 은 `coupang` / `center` / `delivery`, 지난 자료는 `status` 를 `confirmed` 로 넣습니다.

## 2-1. 휴대폰 알림 켜기(웹 푸시, 무료)
화면이 꺼져 있어도 더한물류 휴대폰에 **새 요청 · 취소 · 변경 · 질문**, 관리자에게 **회차 · 기사 취소 · 답변 · 매장 요청**, 매장에 **배차 완료** 알림이 옵니다.
1. Supabase › **Edge Functions › Deploy a new function › Via Editor** → 이름 `notify` → `supabase/functions/notify/index.ts` 내용을 붙여넣고 Deploy.
2. **Edge Functions › Secrets** 에 `VAPID_PUBLIC` · `VAPID_PRIVATE` · `KK_SECRET` 추가(값은 내 PC 폴더의 `_비공개_알림키.txt`, GitHub에는 안 올라감).
3. 같은 파일 아래쪽 SQL(`app_config`)을 프로젝트 주소 · anon 키로 바꿔 SQL Editor 에서 실행.
4. 휴대폰에서 링크를 열고 **알림 켜기**. 아이폰은 사파리 공유 버튼 › **홈 화면에 추가** → 그 아이콘으로 연 뒤 알림 켜기(iOS 16.4 이상).
- 화면을 열어 둔 상태에서는 알림 없이도 소리 · 진동 · 안내가 바로 뜹니다.
- 홈 화면 아이콘이나 알림을 누르면 그 휴대폰에서 마지막으로 쓴 화면(더한물류 · 매장)으로 바로 열립니다.

## 2-2. 구글시트 1시간마다 가져오기
「킹콩_쿠팡배차내역」 · 「매장출고_고객배송내역」 · 「배차내역_경산2」의 최근 45일 줄을 1시간마다 통합 대장에 넣습니다(시트를 공개로 바꾸지 않음).
1. Supabase › Edge Functions › Deploy a new function › Via Editor → 이름 `sheet-sync` → `supabase/functions/sheet-sync/index.ts` 붙여넣고 Deploy.
2. Edge Functions › Secrets 에 `SHEET_SECRET` 추가(값은 `_비공개_알림키.txt`).
3. https://script.google.com → 새 프로젝트 → `google-apps-script/시트_자동보내기.gs` 내용을 붙여넣고, 위 3줄(ENDPOINT · SECRET · ANON_KEY)을 채우기 — 시트 3개를 볼 수 있는 구글 계정으로.
4. 함수 '설치' 실행 → 권한 허용. 이후 1시간마다 자동. 지난 자료 전체는 '전체보내기' 한 번.
- 같은 날 · 같은 구간 요청이 앱에 이미 있으면 그 줄에 붙습니다(중복 없음). 확인 · 정산 확정된 줄은 덮어쓰지 않고, 동기화 때는 알림을 보내지 않습니다.
- 시트에서 온 줄은 대장에 '시트' 표시 — 테스트 기간엔 시트가 원본이라 시트에서 고칩니다.
- 경산2 시트의 운송사는 **한국파렛트풀**로 들어갑니다(업체 등록 필요: 아래 SQL).

## 2-3. 본사 확인(최종 완료)
운행 완료 → **확인 담당자 '확인'** → 정산 확정. 확인 전 건이 있으면 정산 확정 버튼이 잠깁니다. 더한물류가 확인된 건을 고치면 다시 '운행 완료'로 돌아가 재확인.
```sql
insert into checkers(name, pin_hash) values ('본사물류', crypt('여기PIN', gen_salt('bf')));
insert into vendors(name, pin_hash, types) values ('한국파렛트풀', crypt('여기PIN', gen_salt('bf')), '{coupang}');
```
링크: `…/kingkong-dispatch/?c=본사물류` (데모 PIN 4321)

## 2-5. 일별 백업 · 삭제(휴지통) · 엑셀 양식 (build 11)
- **일별 백업**: `ledger_backups` 표에 하루 한 번 대장 전체를 저장(90일 보관). Supabase › Database › Extensions 에서 **pg_cron** 을 켜고 schema.sql 을 다시 실행하면 매일 00:05(한국시간) 자동. 안 켜도 그날 처음 들어온 관리자 화면이 백업을 만듭니다. 설정 › 일별 백업에서 날짜별 엑셀 · 원본(JSON) 받기.
- **삭제**: 진짜 지우기는 DB가 막고, 삭제 권한자만 '휴지통'으로 보냅니다(사유 필수 · 확인 체크 · 빨간 확인 배너). 설정 › 휴지통에서 되살리기. 권한자 지정: `update staff set can_delete = true where email = '이메일';`
- **엑셀(시트 양식)**: 통합 대장 · 정산의 엑셀 버튼은 「킹콩_쿠팡배차내역」과 같은 칸 · 색(하늘색 킹콩 / 분홍 더한물류 / 회색 수식) · 합계(공급가액 · 세액 · 합계금액 · 차액)로 유형별 탭을 만들고, 마지막 탭에 앱 대장 전체 칸을 넣습니다.

## 3. 보안 구조
- 테이블은 RLS 로 잠겨 있어 **로그인한 킹콩 관리자(staff 표에 있는 이메일)만** 직접 읽고 씁니다.
- 업체는 테이블에 직접 닿지 않고, PIN 을 확인하는 함수 4개(`vendor_list` · `vendor_save` · `vendor_add` · `vendor_refs`)로만 자기 업체 건을 봅니다.
- PIN 은 bcrypt 로 저장. 바꾸려면 `update vendors set pin_hash = crypt('새PIN', gen_salt('bf')) where name = '…';`
- 정산 확정(`confirmed`)된 건은 업체가 고칠 수 없고, 모든 수정은 `audit_log` 에 남습니다.
- 고객 개인정보는 `dispatch_delivery` 에 따로 있고 고객배송을 맡은 업체에만 보입니다.
